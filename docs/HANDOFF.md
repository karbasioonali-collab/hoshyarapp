# هوشیار (HOSHYAR) — سند انتقال دانش پروژه

## خلاصه
اپ موبایل اندروید برای مدیریت مالی شخصی با ویس و هوش مصنوعی. کاربر با صدا یا تایپ می‌گه «سوپر ۲ تومن» یا «قسط بانک ماهی ۲ تومن، ۱۳ ماهه، روز ۲۳»؛ AI تشخیص می‌ده کجا ثبت بشه، ثبت می‌کنه و همه‌جای مرتبط (موجودی بانک، جمع‌ها، نمودارها) هم‌زمان به‌روز می‌شه. بخش مشاوره از روی تاریخچه‌ی هزینه‌ها راهکار می‌ده. علاوه بر مالی: مناسبت‌ها، جلسات و قرارها، یادآوری‌ها. قراره در آینده سوپراپ بشه، پس معماری باید ماژولار و قابل‌توسعه باشه.

## نحوه‌ی کار با صاحب پروژه
- فارسی، ساده، صمیمی، غیررسمی. برنامه‌نویس حرفه‌ای نیست، قدم‌به‌قدم و بدون فرض دانش فنی توضیح بده.
- دستورهای ترمینال رو یکی‌یکی و قابل کپی‌پیست بده.
- از روی گوشی کار می‌کنه. اگه چیزی رو اشتباه فهمیدی و اصلاح کرد، دقیق اعمال کن و فرض اضافه نکن.
- مدل کار: اول ساختار و شکل کامل بشه، اتصال‌های بیرونی (AI، پیامک) بعداً.

## اصول
1. ساده و قابل‌فهم برای همه‌ی سنین (نه اختصاصی یه قشر) و در عین حال شیک و مدرن.
2. هدف اصلی: کار با ویس. کاربر بگه، سیستم تحلیل کنه و انجام بده.
3. اصل حسابداری: هر تغییر عددی (دستی، ویس، خودکار) فوری و هم‌زمان همه‌جا اصلاح بشه.
4. قابل‌توسعه: افزودن ستون/جدول/صفحه/دسته‌ی جدید بدون بازنویسی. دسته‌بندی‌ها رکورد دیتابیس‌اند، نه هاردکد.
5. Fallback: ویس کار نکرد ← تایپ. صدا کار نکرد ← متن. متن همیشه در دسترسه.

## استک
- اپ: React Native + Expo (expo-router، NativeWind، فونت Vazirmatn، RTL)
- بک‌اند: Next.js API روی Liara. دیتابیس: PostgreSQL + Prisma روی Liara
- پنل ادمین: Next.js جدا (apps/admin)
- state: TanStack Query + Zustand. نمودار: react-native-gifted-charts. ضبط صدا: expo-av
- ساختار: monorepo با npm workspaces: apps/backend، apps/admin، apps/mobile، packages/database، packages/shared
- توزیع: کافه‌بازار/مایکت + APK مستقیم از سایت. ساخت APK با EAS Build. iOS فعلاً کنار گذاشته شده (بعداً TestFlight یا PWA).
- هوش مصنوعی: سرویس‌های خارجی از ایران فیلترن، پس واسط ایرانی (آوالای یا متیس). اینترفیس abstract در packages/shared/src/ai-provider.ts با سه متد transcribe، chatComplete، synthesizeSpeech. انتخاب provider با env: AI_PROVIDER=avalai|metis. فعلاً stub است.
- پیامک OTP: SmsProvider abstract، فعلاً stub (بعداً کاوه‌نگار/ملی‌پیامک).
- احراز هویت: OTP موبایل + ایمیل/رمز (bcrypt + JWT).

## دیتابیس (۱۷ مدل)
User، OtpCode، AdminUser، BankAccount، Category (branch ثابت: INCOME/INSTALLMENT/EXPENSE/DEBT/RECEIVABLE/ASSET، parentId برای زیرشاخه، userId=null یعنی دسته‌ی پیش‌فرض)، Transaction (لجر مرکزی)، InstallmentPlan، InstallmentPayment، PersonLedgerEntry (بدهی/طلب)، Asset، Event، Appointment، Reminder، OnboardingAnswer، ColumnLabelOverride (تغییر نام ستون توسط کاربر)، LedgerEvent (پیام ساده‌ی فارسی برای UI)، VoiceInteraction.
سرویس مرکزی ledger-service: تنها نقطه‌ی ورود هر تغییر مالی (recordTransaction، updateTransaction، deleteTransaction، payInstallment، settlePersonEntry) داخل prisma.$transaction اتمیک و با خروجی LedgerEvent.

## قوانین سراسری UI
1. به‌جای «توضیحات» بنویس «شرح»، به‌جای «اصلاح» بنویس «ویرایش».
2. ستون اول جدول (ردیف) ثابت؛ نام بقیه‌ی ستون‌ها قابل تغییر توسط کاربر.
3. جای ثابت دکمه‌ها در همه‌ی صفحات: سمت راست = افزودن دستی، سمت چپ = میکروفون.
4. ویرایش و حذف کنار هم. دکمه‌ی حذف همیشه قرمز.
5. روز/ماه/ساعت کشویی. تاریخ شمسی. ساعت ۲۴ساعته.
6. آخرین باکس دسته‌بندی همیشه خالیه تا کاربر دسته‌ی جدید بسازه (نامحدود، بعد از هر افزودن یه باکس خالی دیگه می‌مونه).
7. هر صفحه انتخاب بازه‌ی زمانی داره.
8. نمودار ستونی در همه‌ی صفحات: زیرمجموعه = روند همون آیتم در ماه‌های گذشته، والد = مقایسه‌ی همه‌ی زیرمجموعه‌ها. نمودار خالی ← پیام ساده «اطلاعات وارد کنید».
9. هر صفحه دکمه‌ی چشم‌گیر «بازگشت به صفحه اصلی» داره.
10. رنگ نمودار خلاصه‌ی حساب‌وکتاب: درآمد=سبز، اقساط=نارنجی، هزینه‌های جاری=قرمز، طلب‌ها=آبی، بدهی‌ها=بنفش، دارایی‌ها=زرد.

## نقشه‌ی صفحات
صفحه اصلی: بالا ورودی AI (میکروفون/تایپ)، بالا-راست منوی ۳خط (صفحه اصلی، تنظیمات، پشتیبانی، پروفایل، ورود و ثبت‌نام)، و ۵ سرشاخه: حساب و کتاب، مناسبت‌ها، جلسات و قرارها، یادآوری‌ها، مشاوره.

حساب و کتاب (نمودار خلاصه‌ی رنگی + «درآمد این ماه») با هفت زیرمنو:
- بانک: ردیف، نام بانک، موجودی، شرح. ویرایش دستی و به‌روزرسانی خودکار هر دو هم‌زمان فعال.
- درآمد: کل درآمد و درآمد ماه جاری + نمودار. زیرمجموعه‌ها (هرکدوم صفحه و جدول جدا): حقوق، سود کار و پیشه، اجاره دریافتی، سود سهام (نام شرکت، مبلغ)، طلب، قرض، فروش.
- هزینه‌های جاری: جمع هزینه‌ها، هزینه‌های ماه جاری، بازه، نمودار. زیرمجموعه‌ها: اجاره پرداختی، رستوران و کافه (ردیف، نام رستوران، مبلغ)، خرید، مواد غذایی (سوپر، گوشت، مرغ و ماهی، نان و شیرینی، میوه، سایر)، تاکسی، تعمیرات، سفر، پزشکی، تفریحات، شارژ و قبض. «اجاره دریافتی» (درآمد) با «اجاره پرداختی» (هزینه) قاطی نشه.
- اقساط: ردیف، شرح، مبلغ کل قسط، قسط هر ماه، تعداد اقساط، تاریخ پرداخت هر ماه (فقط روز). با ثبت قسط، رکوردهای ماهانه خودکار ساخته می‌شه. وقتی کاربر بگه «قسط رو دادم» (هر زمان): قسط پرداخت‌شده علامت می‌خوره، از موجودی بانک کم می‌شه، از کل بدهی کم می‌شه. اپ به واریز بانکی دسترسی نداره.
- بدهی به اشخاص: ردیف، شرح، نام، مبلغ، ماه پرداخت، روز پرداخت.
- دارایی‌ها: ردیف، شرح، میزان (بدون واحد ثابت؛ پول/ملک/طلا).
- طلب از اشخاص: جمع کل طلب، طلب این ماه، بازه؛ ردیف، شرح، نام، مبلغ، ماه دریافت، روز دریافت.
مناسبت‌ها (تولد، سالگرد): ردیف، شرح رویداد، ماه، روز.
جلسات و قرارها: ردیف، شرح، ماه، روز، ساعت، محل.
یادآوری‌ها: ردیف، شرح (ستون بزرگ‌تر)، ماه، روز، ساعت. بازه‌ی یادآوری (۱ روز/۲ روز/یک هفته قبل) از تنظیمات کنترل می‌شه. اعلان فقط داخل اپ (بدون Push واقعی).
مشاوره: بالا توضیح «در این صفحه شما از سیستم مشاوره می‌گیرید». کاربر مثلاً می‌گه «می‌خوام دو ماه دیگه سفر برم» و AI از روی تاریخچه‌ی هزینه‌ها راهکار می‌ده. ورودی: تایپ یا میکروفون. این صفحه پنجره‌ی چت می‌خواد.
Onboarding اولین ورود: درآمد ماهانه، اجاره/قسط خونه، هزینه/قسط ماشین، سایر هزینه‌های ثابت.

## رفتار AI و ویس
- مسیر: POST /api/ai/intent ← STT ← LLM با function-calling (add_transaction، pay_installment، navigate، ask_clarification) ← اجرا از طریق ledger-service ← پاسخ: پیام فارسی + مقصد ناوبری + صوت (اختیاری).
- ویس در همه‌ی صفحات کار می‌کنه؛ سیستم خودش صفحه‌ی مرتبط رو باز و ثبت می‌کنه (فقط راهنمایی نه). اگه اطلاعات ناقص بود (مثلاً کدوم بانک؟) همونجا می‌پرسه.
- فیدبک: کامل ثبت شد ← «ثبت شد ✅ لطفاً بررسی کنید درست باشه»؛ ناقص بود ← «بعضی قسمت‌ها کامل نشد، دوباره بگید یا خودتون وارد کنید» و مشخص کن چی کم بود.
- کنار هر پاسخ سیستم آیکون پخش صدا (▶️) باشه (صدا اختیاری، متن همیشه هست).
- مشاوره: پنجره‌ی چت با حباب مکالمه، متن کامل قابل‌اسکرول، دکمه‌ی پخش صدا، و تاریخچه‌ی قبلی.

## وضعیت فعلی
انجام شده (فاز اول، شاخه‌ی claude/hoshyar-project-setup-ht4vrx): مونوریپو، ۱۷ مدل، ledger-service، لایه‌ی abstract، حدود ۳۵ روت بک‌اند، پنل ادمین (لاگین/داشبورد/کاربران/تراکنش‌ها)، و اپ موبایل با تمام صفحات (طبق گزارش، کارکن)، کیت UI مشترک، بدون خطای TypeScript، باندل Metro موفق. یک تعارض نسخه‌ی react-native/metro/reanimated با overrides در package.json ریشه حل شد.
انجام نشده (بعداً): پنجره‌ی چت مشاوره، فیدبک تکمیل‌بودن ویس، دکمه‌ی پخش صدا، اتصال واقعی AI و پیامک (stub است، پس ویس عملاً هنوز کار نمی‌کنه)، گسترش ویس به بانک/بدهی/طلب/دارایی، فونت فارسی اختصاصی، تست روی دستگاه واقعی، دیپلوی روی Liara، تکمیل پنل ادمین و تنظیمات/پروفایل/پشتیبانی، build APK.
ابهام: طرح اولیه فقط درآمد رو کامل می‌خواست، ولی گزارش فاز اول می‌گه همه‌ی صفحات کارکنن؛ تا اپ واقعاً اجرا نشه معلوم نیست عمق کارکردی همه‌ی صفحات کامله.

## مشکل تست
- سندباکس Claude Code به exp.host و api.expo.dev دسترسی نداره، پس npx expo start باید روی دستگاه خود کاربر اجرا بشه.
- روی Termux: npm install موفق بود ولی npx expo start خطا داد، چون پکیج lightningcss (وابستگی NativeWind) باینری سازگار با Termux نداره. نصب rust و rebuild جواب نداد. مشکل از کد نیست، از محیطه. راه‌حل: اجرا روی کامپیوتر ویندوز ۱۰/۱۱، مک یا لینوکس.
- روش اجرا: git clone، git checkout claude/hoshyar-project-setup-ht4vrx، npm install، cd apps/mobile، کپی .env.example به .env، npx expo start، اسکن QR با Expo Go. برای تست کامل، بک‌اند و PostgreSQL هم باید در دسترس باشن.

## قدم‌های بعدی
1. دیدن اپ روی کامپیوتر و جمع‌آوری ایرادها در یک پیام.
2. افزودن پنجره‌ی چت مشاوره، فیدبک ویس، دکمه‌ی پخش صدا و کامل‌کردن همه‌ی صفحات با کیفیت «درآمد».
3. فونت فارسی، پنل ادمین کامل، تنظیمات/پروفایل/پشتیبانی.
4. اتصال AI واقعی (آوالای/متیس؛ کلید API رو صاحب پروژه از پنل سرویس می‌گیره) و بعد پیامک.
5. دیپلوی روی Liara به‌صورت برنامه‌ی جدید و جدا.
6. build APK با EAS و انتشار.
7. بعداً: iOS/PWA، Push Notification، توصیه‌ی سرمایه‌گذاری.
